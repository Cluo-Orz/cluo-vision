# Cluo Vision 整体架构设计

> 版本: v1.0 | 日期: 2026-07-05 | 状态: 草案

---

## 一、项目概述

Cluo Vision（Cluo 视界）是一个面向**电视大屏**和**手机移动端**的家庭影院应用。系统由三部分组成：

1. **本地服务端** — 部署在 Linux + NAS 上，负责媒体管理、自动化下载、API 聚合
2. **客户端 App** — 运行在雷鸟电视（Android TV）和手机（Android/iOS）上
3. **外部资源网络** — PT/BT 站点、RSS 订阅源，作为内容获取渠道

核心功能分为两大块：

| 功能 | 说明 |
|------|------|
| **找片** | 浏览资源站、搜索影片、发起下载、查看下载进度 |
| **看片** | 浏览已下载的媒体库、播放视频（支持 4K HDR/DV）、收藏/历史 |

## 三、技术栈选型

### 3.1 客户端 App — Flutter

| 维度 | 选型 | 理由 |
|------|------|------|
| **框架** | **Flutter 3.x** | Google 在 2025 年大幅加强了 Android TV D-pad 优化；Impeller 引擎实现 60fps 流畅 UI；一套代码覆盖 Android TV + Android 手机 + iOS |
| **状态管理** | Riverpod 2.x | 编译时安全、无 Context 依赖、适合复杂异步场景 |
| **视频播放** | media_kit (基于 libmpv) | 支持 4K HDR/DV 硬解、ASS 字幕渲染、多音轨切换 |
| **网络层** | dio + retrofit | HTTP 请求 + API 类型生成 |
| **数据库** | drift (SQLite) | 本地缓存（播放历史、下载进度等） |
| **TV 适配** | flutter_tv + FocusNode 体系 | D-pad 焦点管理、遥控器事件 |

**为什么不用 React Native？**

- RN 在 TV 端的 D-pad 支持需要大量自定义实现
- RN 的 JS Bridge 在视频重场景下容易出现掉帧
- Flutter 的 Impeller 渲染引擎在低性能 TV 芯片上表现更好

**为什么不用 Kotlin Multiplatform？**

- 缺少 iOS 端覆盖（用户可能需要）
- 生态成熟度不如 Flutter

### 3.2 服务端

| 组件 | 选型 | 说明 |
|------|------|------|
| **媒体服务器** | **Jellyfin** | 完全免费开源、硬件转码免费、无外网依赖（离线可用）、Android TV 客户端生态好 |
| **媒体请求** | **Jellyseerr** | 精美的影片发现/请求界面，对接 Jellyfin + Sonarr/Radarr，支持中文 |
| **TV 剧管理** | **Sonarr** | 自动追剧：RSS 监控 → 匹配质量配置 → 推送下载 → 重命名归档 |
| **电影管理** | **Radarr** | 自动下载电影：搜索 → 匹配 → 推送 → 归档 |
| **索引器管理** | **Prowlarr** | 统一管理所有 BT/PT 站点索引，自动同步到 Sonarr/Radarr |
| **下载客户端** | **qBittorrent** | 轻量高效，WebUI 管理，支持 RSS/分类/做种 |
| **字幕** | **Bazarr** + **ChineseSubFinder** | 自动下载中文字幕 |
| **动漫追番** | **AutoBangumi** | 专为动漫设计的 RSS 自动下载 + 自动重命名 + Jellyfin 刮削 |
| **反向代理** | **Caddy** (或 Nginx) | 自动 HTTPS、反向代理各服务 |
| **自定义后端** | **cluo-vision-server** (Go/Node.js) | API 聚合层，统一认证、状态管理 |

### 3.3 为什么选 Jellyfin 而不是 Plex/Emby？

| 对比维度 | Jellyfin | Plex | Emby |
|----------|----------|------|------|
| 费用 | **完全免费** | 硬件转码需 Plex Pass ($750 终身) | 硬件转码需 Premiere ($119) |
| 开源 | ✅ GPL | ❌ 闭源 | ❌ 部分闭源 |
| 离线可用 | ✅ 零外网依赖 | ❌ 认证需连 Plex 服务器 | ✅ 本地认证 |
| 硬件转码 | ✅ 免费内置 | 🔒 付费 | 🔒 付费 |
| Android TV 客户端 | 官方 + Yamby + AfuseKt | 优秀 | 一般 |
| 隐私 | 零遥测 | 收集用户数据 | 较少遥测 |

**结论：** Jellyfin 是家庭影院的最佳选择。免费、隐私友好、离线可用，且 Android TV 客户端生态在 2025 年已相当成熟。

### 4.3 两种下载模式

#### 模式一：精确请求（推荐日常使用）

```
用户流程:
  1. 在 Cluo App / Jellyseerr 中搜索影片名称
  2. 系统查询 Sonarr/Radarr，展示匹配结果
  3. 用户选择想要的版本（1080p / 4K / 原盘）
  4. Sonarr/Radarr 自动通过 Prowlarr 搜索资源
  5. 找到后推送到 qBittorrent 下载
  6. 下载完成 → 自动重命名 → 移动到媒体库 → Jellyfin 刮削
  7. 用户在"看片"模块中即可观看

优点: 精准、自动化程度高、文件命名规范
缺点: 依赖 Prowlarr 能搜到（冷门/老资源可能搜不到）
```

#### 模式二：手动下载（补充）

```
用户流程:
  1. 在 Cluo App 中浏览资源站列表
  2. 点击站点跳转（或内置 WebView 搜索）
  3. 手动下载 .torrent 文件
  4. 上传到 qBittorrent WebUI
  5. 下载完成后，手动分类到对应文件夹
  6. Jellyfin 自动扫描入库

优点: 覆盖所有资源站，不遗漏
缺点: 需要手动分类，命名可能不规范导致刮削失败
```

### 5.2 数据流

```
【找片流程】
Cluo App → cluo-vision-server → Jellyseerr/Sonarr/Radarr → Prowlarr → PT/BT 站点
                                    ↓
                              qBittorrent 下载
                                    ↓
                              Sonarr/Radarr 重命名归档 → NAS 媒体库
                                    ↓
                              Jellyfin 刮削元数据 → 可观看

【看片流程】
Cluo App → cluo-vision-server → Jellyfin API → 返回媒体列表/详情
Cluo App → Jellyfin (直连播放流) → NAS 文件 → 电视硬解播放
```

### 5.3 关于自定义后端 (cluo-vision-server)

**为什么需要一个自定义后端？**

Jellyfin、Sonarr、Radarr、qBittorrent 各自有独立的 API 和 WebUI，但它们是分散的。自定义后端的作用是：

1. **统一入口** — App 只需要对接一个 API，后端负责分发到各服务
2. **统一认证** — 本地账号体系，一个账号管理所有功能
3. **状态聚合** — "找片"的结果需要聚合多源（Sonarr/Radarr 搜索结果 + 下载进度）
4. **体验定制** — 为电视端优化的 API 响应格式（精简字段、适配翻页）
5. **缓存加速** — 热点数据缓存，减少对 Jellyfin API 的频繁调用

**技术选型建议**: **Go (Fiber)** 或 **Node.js (Fastify)**

- Go: 性能好、部署简单（单二进制）、内存占用低、适合 NAS 环境
- Node.js: 生态丰富、JSON 处理天然高效、适合 API 聚合场景

推荐 **Go + Fiber**，编译为单文件部署在 NAS 上，资源占用极小。

### 6.2 TV 端交互要点

| 要点 | 设计规则 |
|------|----------|
| **10-foot UI** | 字号 ≥ 24sp，卡片大小适配 3-5m 观看距离 |
| **D-pad 导航** | 所有可交互元素必须在 FocusNode 树中，焦点状态有明显视觉反馈（放大 + 边框高亮） |
| **网格布局** | 横滑 + 竖滑组合，每行 4-6 个卡片 |
| **遥控器映射** | 上下左右=导航，确认=进入/播放，返回=退出，菜单=更多选项 |
| **播放控制** | 方向键上下=音量，左右=快进快退，确认=暂停/播放 |
| **文本输入** | 尽量用语音输入或手机扫码输入，避免遥控器打字 |

### 6.3 手机端差异

- 触控操作，纵向滚动为主
- 支持横屏播放
- 可作为 TV 遥控器（通过局域网通信）
- 支持投屏到 TV（如果 Jellyfin 不支持直接投屏，可用 DLNA）

## 九、技术风险与应对

| 风险 | 应对策略 |
|------|----------|
| PT 站邀请难度大 | 优先从 BTSCHOOL 入门，M-Team 可捐赠入站，节日留意开放注册 |
| 4K 高码率播放卡顿 | TV 用有线网络，Jellyfin 开启硬件转码（Intel QSV），降级到 1080p 兜底 |
| 字幕刮削不准确 | 文件命名严格遵循规范，Bazarr + ChineseSubFinder 双保险 |
| Flutter TV 生态不够成熟 | 调研确认 media_kit 在 MT9655 上的硬解兼容性，必要时降级到 ExoPlayer |
| PT 做种占用上传带宽 | qBittorrent 设置限速，做种时间配额管理 |
| 雷鸟电视侧载 APK 限制 | Android 14 允许侧载（开发者选项），灵控系统不限制 APK 安装 |
